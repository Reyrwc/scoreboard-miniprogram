# 记分板 — 产品需求文档 (PRD)

## 一、项目概述

**产品名称**：记分板  
**小程序名称**：记分板  
**产品形态**：微信小程序  
**目标用户**：线下多人棋牌、桌游等需要实时记分的场景  
**核心价值**：替代纸质记分，多人实时同步，自动统计战绩

### 1.1 问题陈述

线下棋牌记分目前依赖纸笔记录，存在以下痛点：
1. **易丢失/记错**：纸笔记分容易丢失、记错、字迹不清
2. **仪式感不足**：每次打牌都要找纸找笔，体验割裂
3. **无法实时排名**：所有人当前积分排名无法即时可见
4. **历史无法回顾**：过往战绩无法统计和查看

### 1.2 目标用户

18-35岁为主，每周约1次线下棋牌聚会的年轻人。过年期间可能扩展到长辈群体。

### 1.3 成功指标

| 指标 | 优先级 | 说明 |
|------|--------|------|
| 留存率 | ⭐⭐⭐⭐⭐ | 用户下次打牌还会用这个小程序 |
| 分享率 | ⭐⭐⭐⭐ | 自然传播，一人带动一群人 |
| 日活/周活 | ⭐⭐⭐ | 有稳定使用用户 |

## 二、账号体系

| 项目 | 说明 |
|------|------|
| 登录方式 | 微信授权登录（wx.login） |
| 默认信息 | 头像、昵称取自微信授权数据 |
| 修改信息 | 支持修改头像和昵称，修改后以最新为准 |
| 多设备登录 | 支持同一账号多台手机同时在线 |

## 三、房间系统

### 3.1 创建房间
- 点击"创建房间"生成新房间
- 房间名称：**房主昵称 + "的房间"**（如"张三的房间"）
- 创建者自动成为**房主**

### 3.2 邀请加入
- 生成**分享链接**和**二维码**
- 好友通过链接/扫码进入房间，自动成为玩家
- 房间最多支持 **20 人**

### 3.3 房间规则
| 规则 | 说明 |
|------|------|
| 单房间限制 | 每个用户同一时间只能加入一个房间 |
| 房主退出 | 自动转移给第二个进入房间的人 |
| 退出房间 | 玩家可随时退出，**分数保留** |
| 重新加入 | 退出后可重新加入同一房间（房间未解散时） |
| 解散房间 | 仅房主可操作，解散后链接/二维码失效 |
| 自动解散 | **30 分钟内无人记分**，房间自动解散 |
| 数据保留 | 房间解散后，数据保存到历史战绩 |

## 四、记分系统（核心）

### 4.1 记分逻辑

**核心规则**：
- 点击某玩家头像 → 给该玩家**加分**（只能输入正数）
- 加分时，**记分人自动扣减**相应分数
- 例如：A给B记+5分 → B+5，A-5（自动）

**示例场景**：
- A被B杠了 → A点击B头像，输入+3 → B+3，A-3
- C胡了，A输给C → A点击C头像，输入+10 → C+10，A-10
- D被A杠了 → D点击A头像，输入+3 → A+3，D-3

### 4.2 记分交互
1. 在记分界面**点击玩家头像**
2. 弹出记分输入框
3. 输入**分数**（必填，**只能输入正数**，支持小数点后1位，如 5.0、2.5）
4. 输入**备注**（选填，自由文本，如"自摸"、"杠"、"胡"）
5. 点击确认提交

### 4.3 记分规则
- **任何人**随时可以给**任何人**记分（不包括自己给自己加分）
- 记分人自动扣减相应分数
- 分数**累计**，不随"下一局"重置

### 4.4 下一局
- 界面有"下一局"按钮，**任何人都可以点击**
- **限制**：当前局必须至少有 **1 条记分记录**，否则点击无效
- **初始状态**：进入房间不显示局数
- **触发后**：第一次点击"下一局"后，显示"第 1 局"
- 后续每点击一次，局数 +1
- **防重复点击**：有人点击"下一局"后，**1 分钟内**其他人再次点击无效，提示"刚刚有人点击了下一局，请一分钟后重试"

### 4.5 网络处理
- **无本地缓存**，断网无法记分
- 记分提交时显示**加载状态（转圈）**
- 成功 → 从服务器刷新记分列表
- 失败 → 提示网络异常，不显示该记录
- **记分列表始终从服务器获取**

### 4.6 界面布局
- 上方：玩家头像区域，**响应式布局（最少4列，最多5列）**，圆形头像，下方显示昵称和当前积分
- 玩家按**积分从高到低排序**，实时刷新
- **最后一个头像永远是"+"按钮**，用于邀请好友加入房间
- 响应式列数规则：
  - 1-4个玩家：4列
  - 5个玩家：5列
  - 6-8个玩家：4列
  - 9个以上玩家：5列
- 下方：**记分详细记录列表**，按时间倒序显示每一笔记分（谁给谁、几分、备注、时间）

## 五、结算报告

触发条件：房主**结束房间**或**解散房间**时生成

### 5.1 结算内容
- 房间名称
- 对局数（总轮次）
- 所有玩家**最终积分排名**
- 每位玩家的总赢分/总输分

### 5.2 结算查看
- 房间解散后，所有玩家均可在历史战绩中查看结算

---

## 六、历史战绩

### 6.1 列表展示
- 按**日期从新到旧**排列
- 每条记录显示：
  - 房间名称
  - 日期
  - 参与玩家及其分数
  - 对局数（轮次）

### 6.2 规则
- **不支持删除**历史记录
- 房间解散后自动保存

---

## 七、个人统计

展示该用户的所有历史数据汇总：

| 指标 | 说明 |
|------|------|
| 总场次 | 参与的房间总数 |
| 总胜场 | 积分排名第一的场次 |
| 总赢分 | 所有房间累计赢分 |
| 总输分 | 所有房间累计输分 |
| 净得分 | 总赢分 - 总输分 |
| 最高连胜 | 连续获胜的最高次数 |
| 最大单局赢分 | 单个房间最高赢分 |
| 最大单局输分 | 单个房间最低得分 |
| 平均每局得分 | 净得分 / 总场次 |
| 最常用房间 | 使用次数最多的房间名称 |
| 最常一起玩 | 一起玩过最多次的好友 |

**注意**：个人统计页面不显示趋势信息（如"较上周 +120"），保持简洁。

---

## 八、好友排行

### 8.1 数据来源
- 基于房间历史记录，统计**曾一起游戏的玩家**
- 从 `history` 集合中提取当前用户参与过的所有房间，获取同房玩家列表
- 无法获取微信好友关系链（微信小程序已于 2022 年全面关闭关系链接口）

### 8.2 排行展示
- 支持按**胜率**、**总场次**、**净得分**排序
- 默认按**胜率**从高到低排序
- 每位好友显示：
  - 胜率
  - 总场次
  - 总胜场
  - 总赢分

## 九、页面结构

### 9.1 底部导航栏
- **只有两个 Tab**：首页、我的
- 通过首页可以进入：创建房间、扫码进房
- 通过"我的"可以进入：历史战绩、个人统计、好友排行

### 9.2 页面列表

```
pages/
├── index/          # 首页（头像居中 + 统计 + 创建/扫码按钮）
├── room/           # 房间内（响应式记分界面）
├── history/        # 历史战绩列表
├── historyDetail/  # 历史战绩详情
├── stats/          # 个人统计（无趋势信息）
├── friends/        # 好友排行
└── profile/        # 我的（个人资料 + 设置菜单）
```

### 9.3 首页设计
- 头像居中，下方显示昵称
- 昵称下方显示简洁统计信息：总场次、胜率、净得分
- 统计信息下方两个大按钮：创建房间、扫码进房
- **不显示历史记录**

### 9.4 我的页面
- 顶部：头像 + 昵称 + ID + 编辑按钮
- 快捷统计：总场次、胜率、净得分
- 菜单分组：
  - 我的数据：历史战绩、个人统计、好友排行
  - 设置：消息通知、深色模式
  - 其他：退出登录

## 十、技术架构

### 10.1 技术选型
| 层级 | 方案 |
|------|------|
| 前端 | 微信小程序原生开发 |
| 后端 | 微信云开发（CloudBase） |
| 数据库 | 云开发数据库（MongoDB） |
| 实时同步 | 云开发实时推送 |

**rooms 集合**
```json
{
  "_id": "房间ID",
  "name": "房间名称",

  "players": [
    {

      "nickname": "昵称",

      "joinedAt": "加入时间"

  "currentRound": 0,
  "lastNextRoundTime": null,

  "lastScoreAt": "最后记分时间",
  "dissolvedAt": "解散时间"
```

```json
{
  "_id": "openid",
```
